# Skill · 通用（所有题型都读）

> 这份文件每次解题都会被加载。往里加的东西要**短、准、能直接照做**。

## 0. 这个平台的规则

- flag 格式：`NSSCTF{...}`。附件里如果是 `GWHT{}` / `flag{}`，要换前缀。
- 每题限时 **3600 秒**，超时作废。
- 每题 **20 次**提交机会，交错了会扣分（rating 是 Elo）。
- 一次只能挂一道题，做完才能领下一道。

## 1. 开工第一件事：判断"给的信息够不够"

按顺序问自己三句：

1. **有附件吗？** 有就先看附件（预侦察里已经列出来了）。
2. **有远程地址吗？** 有就先连上去看它给什么提示。
3. **题目说明里有线索吗？** 有些题的 `content` 是**平台免责声明**（"本题目复现环境尚未取得授权…"），
   那不是题面，别当成线索分析半天。

**两个都没有**时：不要凭空猜，用 `need_human` 请用户看看平台有没有环境入口。

## 2. 常见的"零信息"题

有些题看着什么都没有，其实是：

- **猜谜 / 造词类**（flag 可能是英文短句的 leetspeak）
- **平台本身给了线索，只是藏在 content 里**
- **真的缺环境**（这时候硬猜是浪费时间）

区分方法：先 `finish` 前问自己"我有没有任何可验证的依据"。没有就别交，说明卡在哪。

## 3. 写代码的规矩

- **脚本一律 `write_file` 写文件，再 `run_cmd python xxx.py` 跑。**
  不要用 `python -c "..."`——引号会被 shell 改写，报错还看不懂。
- 脚本开头加 `# -*- coding: utf-8 -*-`，输出尽量 ASCII，避免控制台编码问题。
- 调试信息一次打够（长度、前 16 字节、关键变量），别一步步试。

## 4. 什么时候必须停

- 同一条路试了 3 次没进展 → 换方向。
- 步数过半还没摸到"可利用的点" → 准备 `finish` 并在说明里写清楚进度。
- 千万不要为了"不空手"而瞎编一个 flag 交上去。

## 5. 提交前的自检

1. 格式是 `NSSCTF{...}` 吗？
2. 我是**算**出来的，还是**猜**的？猜的就别交。
3. 有现成的校验手段吗（比如题目自带 checker、或者能本地复现）？有就先跑一遍。

## 6. 先判断这是不是"需要人玩的题"

出现下面任意 **两条**，就不要再试图静态解决了，**直接 `need_human`**：

- 附件是 `.exe` / 游戏 / GUI 程序
- readme 或题面写着 **"按 X 键"**、"点击"、"操作说明"
- 附件里有截图（`source/*.png` 这种）
- 二进制特别大（> 20MB），又没有明显的文件格式或协议
- 要求"达到某个分数 / 建几个东西 / 玩到某关"

**你的处境**：没有屏幕、没有键盘、看不到窗口。这类题你永远做不出来，硬啃等于烧钱。

`need_human` 要写清楚：
- 打开哪个程序（完整路径）
- 按什么键、按几次
- 看哪里（弹窗 / 画面 / 目录里有没有新文件）
- 把结果贴回来

## 7. 防止"瞎试"

这几条是判断自己在不在瞎蒙的信号：

- **2 秒换一个脚本** → 你在蒙。停手，把上一条报错完整读一遍。
- **3 步内写了 3 个不同脚本** → 你在蒙。回去重读题面和【预侦察】。
- **同一个断言连续报错、你只改了数字** → 你在蒙。先想清楚这个数字从哪来。
- **步数过半还没摸到"可利用的点"** → 准备 `finish`，在说明里写清卡在哪。

**每次动手前问一句：我这个动作是为验证哪个假设？** 答不出来就别动手。

# 第二部分：真正的思考方式

上面是规矩，这里是**方法**。规矩让你不犯错，方法让你解得出。

## 8. 拿到一道题，脑子里该跑什么流程

### 第一步：建立"问题空间"（不写任何代码）

用三句话把题描述清楚：

1. **输入是什么？**（一个文件 / 一个地址 / 一段文本 / 一个矩阵）
2. **输出要求是什么？**（flag / 一个数字 / 一段能交互的东西）
3. **中间那个变换是什么？** ← **这一句决定一切**

第三句答不出来就先别写脚本。**没看清变换就动手，等于闭眼开车。**

**判断"变换类型"的问句**：

| 看到什么 | 说明变换是 | 该往哪想 |
|---|---|---|
| `pow(x, e, n)` / 大素数 | 数论 | RSA 体系、离散对数、模运算性质 |
| 矩阵 / `Matrix` / `vector` | 线性代数 | 秩、核、特征值、相似变换 |
| `xor` 循环 / 字节替换表 | 对称密码 / 混淆 | 找 S 盒、找密钥、差分 |
| base64 / rot13 / 自定义码表 | 编码 | 套娃剥离、码表逆推 |
| HTTP 请求 / 参数拼接 | Web | 注入点、过滤绕过 |
| `scanf` / `read` + 缓冲区 | Pwn | 溢出点、可控长度 |
| 一堆 if-else 比较 | 逆向校验 | 从比较点倒推，别正着算 |

### 第二步：找一个"必须成立的等式"

每道题的核心都是一个约束。找到它，题目就从"猜"变成"解"：

- Crypto：`m^e ≡ c (mod n)`、`R = L·D`、`x = flag`
- Reverse：`check(input) == true`、`encrypt(flag) == target`
- Web：`输入 → 满足某个查询/比较`
- Misc：`文件里藏着 X`、`编码套娃解码后是 flag`
- Pwn：`输入长度 > 缓冲区` 且 `能覆盖返回地址`

**找不到这个等式，说明你还没看懂题。**

### 第三步：看这个等式能不能"倒着走"

- **能倒走**（有逆运算）→ 直接逆，最快
- **不能倒走**（哈希/单向）→ 找弱点、找碰撞、找旁路
- **倒走太慢**（2^128）→ **先别放弃**，问自己：有没有第二个方程的约束把它砍小？

> 血泪教训：一看到"反推要 2^128 次"就下结论"做不了"，是错的。
> 先问：**还有别的条件吗？** 通常有（明文是 ASCII、长度已知、格式固定）。

### 第四步：才动手写代码

写之前先回答三个问题：

1. 这段代码**大概跑多久**？（超 60 秒就要重新想）
2. 跑完我**期待看到什么**？（说不出来就是没想清楚）
3. 如果结果是错的，我**怎么定位是哪一步错**？（提前想好探针放哪）

## 9. 结果不对的时候怎么做（这条最值钱）

**不要**：改个参数重跑。**要**：加探针，把"错"缩小到一行。

### 探针三原则

1. **打一个能证伪的数字**，不是打印一堆东西
2. **打中间态，不打最终态**（最终态你已经知道是错的了）
3. **一次只验证一个环节**

### 真实案例（这次比赛里踩的）

```
现象：求出的特征向量都不像 flag
错误做法：换归一化方式、换 ASCII 区间、换转置 → 全是瞎试
正确做法：打印「零空间维数」
          → 维数是 0
          → 说明 λ 根本不是特征值
          → 说明特征多项式算错了
          → 发现 Berlekamp-Massey 给的是联络多项式，系数要翻转
一共 30 秒定位。
```

**一个数字，胜过十次重跑。**

### 常见的"探针位置"

| 你在算什么 | 打什么 |
|---|---|
| 解方程 / 求根 | 代回原方程是否成立、解的个数、维数 |
| 解密 / 逆变换 | 中间明文长度、是否全部在可打印区间 |
| 逆向校验 | 自己的实现在**已知输入**上和原程序是否一致 |
| Web 注入 | 回显长度、报错内容、响应时间差 |
| 爆破 | 已尝试数量 / 预计总量、命中率 |

## 10. 先小样例，再真数据

**新算法一定要先在 n=3 的小例子上跑通。**

- 自己造数据、自己知道答案
- 30 秒就能验证算法对不对
- 在错误算法上优化性能 = 最浪费时间的做法

真数据（n=42、154 位大数、10 万行日志）只用来做**最后一次**验证。

## 11. 成本和收益的判断

**动手前估一下**：

| 操作 | 大致耗时 | 什么时候值得 |
|---|---|---|
| 纯 Python 循环 10^6 | 1 秒 | 随时 |
| 纯 Python 循环 10^8 | 100 秒 | 只值一次 |
| 纯 Python 循环 10^10 | 3 小时 | 永远不值 |
| 试除法分解 100 位数 | **永远** | 永远不值 |
| 编译 C 跑 10^9 | 几秒 | 值得，先写 C |

**经验法则**：Python 每秒约 10^7 次简单运算。
**超过 2^40 次迭代的方案，回去重新想算法。**

## 12. 什么时候该换方向（而不是继续调）

出现下面任意一条，**停止优化，换思路**：

- 同一个算法改了 3 次还是不对 → 大概率**思路错了**，不是实现错了
- 需要的时间随 n 指数爆炸，而你没法把 n 变小 → 算法类别选错了
- 你在给一个"看起来对但没验证过"的假设加补丁 → 先去验证那个假设

**验证假设比修补实现便宜得多。**

## 13. 收工时机

**看到 flag 形状的字符串并且能说清它从哪来时，立刻 `finish`。**

不要"再确认一下"——多花的每一步都可能让你在最后一步用完。

但也要分清：

- ✅ 从题目环境 / 附件 / 解密结果里拿到的 → 交
- ❌ 源码里的示例、文档里的占位符、自己编的 → 不交

## 14. 一次题目的完整心智模型

```
读题（不写代码）
  ↓
提炼"变换类型"和"核心等式"
  ↓
判断能否反向 / 需要什么额外约束
  ↓
估成本（< 60 秒？）
  ↓
写小样例验证算法
  ↓
上真实数据
  ↓
结果不对 → 加探针定位（不要重写）
  ↓
拿到结果 → 说清来源 → finish
```

**每一步都要问：我现在是在"验证"还是在"猜"？**
猜的时候停下来，回去做验证。
